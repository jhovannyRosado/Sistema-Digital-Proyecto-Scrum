 Sistema Digital – Proyecto Scrum

 1. Descripción del sistema

El Sistema Digital – Proyecto Scrum es un proyecto académico que busca organizar diferentes funcionalidades relacionadas con la gestión y consulta de información académica mediante una plataforma digital.

 2. Objetivo

Desarrollar una propuesta de sistema que facilite el acceso a las funciones académicas, mejore la organización de la información y permita una navegación sencilla para los usuarios.

 3. Problema que resuelve

El sistema busca disminuir las dificultades relacionadas con la consulta de información académica cuando esta se encuentra dispersa o requiere procesos poco prácticos. La propuesta reúne las principales funcionalidades en una plataforma organizada.

4. Funcionalidades principales

 Inicio de sesión.
 Registro de estudiantes.
 Consulta de calificaciones.
 Calendario académico.
 Perfil del usuario.
 Menú de navegación.

 5. Arquitectura seleccionada

Se propone una arquitectura por capas, separando la interfaz de usuario, la lógica de negocio y el almacenamiento de datos. Esta organización facilita el mantenimiento, las pruebas y las futuras mejoras del sistema.

 6. Organización del frontend y backend

 Frontend

El frontend será la parte visual con la que interactúa el usuario. Incluirá las pantallas de inicio de sesión, registro de estudiantes, consulta de calificaciones, calendario académico, perfil y menú de navegación.

 Backend

El backend se encargará de procesar las solicitudes, validar la información, aplicar las reglas del sistema y gestionar las operaciones relacionadas con los datos académicos y los usuarios.

 Comunicación entre frontend y backend

Ambos componentes se comunicarán mediante una API utilizando solicitudes HTTP. Los datos podrán intercambiarse en formato JSON. El backend procesará las solicitudes y devolverá respuestas para que el frontend presente los resultados.

Esta arquitectura describe la organización propuesta y no significa que todas estas funciones estén implementadas actualmente.

El estado de implementación de cada funcionalidad debe verificarse antes de considerarla terminada.
